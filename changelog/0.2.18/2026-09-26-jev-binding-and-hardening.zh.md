# 将 Jev 观察绑定到对应的工具调用，并修复评审发现的缺陷

- **Date:** 2026-09-26
- **Type:** fix
- **Scope:** `core`, `server`, `web`, `docs`

[English](2026-09-26-jev-binding-and-hardening.md)

顾问观察现在是它所描述的那次工具调用上的一条脚注；同时，一次针对本阶段工作的评审找出并修复了一批真实缺陷：被策略拦截的工具被报告为已完成、消息流被割裂、数据根分裂、截止时间被当成用户取消、Benchmark 证据路径上无上限的工作，以及一次因为检查器崩溃而"通过"的评测。

## 细节

- `jev_advisory` hook 事件通过新增的 `toolCallId` 绑定到对应工具调用，并渲染在该调用卡片的数字折叠区里。作为独立的消息流条目时，它会割裂自己落脚的每一个"推理与工具"分组——因为 pre-tool-use hook 恰好在两次工具调用之间触发。没有可绑定调用的观察会被丢弃而不是浮在流中；早于卡片到达的观察则像提前到达的审批决定一样被回填。
- 智能体面板的视图切换改为作用域栏里的一处分段控件，与任务汇总并排，取代了此前手写的、被第二个标签条状标签命名的标签组。两个视图都保持挂载，因此活动日志是一个实时区域：只播报新增行，而不是每次切换都重读全部历史；日志范围也不再随选中不同子 Agent 而改变。提供方的选项枚举已本地化，面板改用应用既有的色调与折叠基元，不再使用一块自成一体的靛蓝卡片，指标标签满足 WCAG AA 对比度。
- 活动日志如实记录发生的事：被策略拒绝的命令显示为已拦截，审批会注明由谁给出，每行都带上执行它的 Agent 与时间戳。其顺序即到达顺序，这是一个全序——此前的比较器会把没有时间戳的工具行与有时间戳的行相互比较，不满足传递性。
- hook 子进程与交互式终端保留 `PENGUIN_HOME`。此前按前缀清除全部 `PENGUIN_*` 变量时，连数据根定位变量一起清掉了，于是一个转而调用 `penguin` 的 hook——这正是 `pathPrepend` 存在的意义——会悄悄操作第二个并行数据根。凭证仍然不会外泄。
- 顾问自身的截止时间现在报告为超时而非取消：截止时间触发的是 SDK 监听的同一个组合信号，慢速提供方此前被归咎于阅读者。它的熔断器改为按时间界定，因此单次运行中的正常并发不再为服务器上所有会话打开熔断。参数键不再原样外发——由模型生成、且形如路径的键只保留最后一段，形似凭证的键会被清理——超出可摘要大小的调用会被报告为已省略，而不是基于残缺内容给出回答。hook 的 stdout/stderr 现在有上限。
- Benchmark 评测证据的读取上限按**请求**而非按会话计算，统计实际参与哈希的字节而不是索引报告的大小，预算耗尽即停止读取，通过 mtime 门控对齐 Trace 索引、仅在缺失时强制重建，读取它所校验过的已解析 Benchmark 路径，并对会话查询分块，使较大的记分板能够返回结果而不是失败。
- 硬约束评估器抛异常的评测用例现在判为失败。此前抛异常的评估器不在门控所遍历的结果数组中，`every()` 因而空洞为真，该用例在没有任何记录的情况下通过。硬约束也在置信度之前检查，且评审模型不再能够推翻它。
- 评测运行可以携带一份清单，把一切能改变答案的输入绑定下来——数据集、评分代码、已评分行、模型的提交号，以及从 git 读出的本仓库自身的提交号——并提供一个离线重新推导每项、逐项指出是哪一项发生了漂移的审计。浮动的模型标签在写入时即被拒绝，因为它是唯一一种事后无法察觉漂移的输入。
- 会把在途调用计入的花费上限。朴素的上限——"是否已花费超过 N"——其实什么也限制不了：一次请求的成本只有在它结束时才知道，因此四个并发调用会在第一个上报之前全部通过检查。现在被放行的调用会先行预留成本，于是无论调用如何交错，`已花费 + 已预留` 始终不超过上限。重复投递的用量事件会被拒绝，而不是被重复计数或悄悄丢弃；无人结算的预留会被回收，而不是把 Agent 永久挡在"无法发起任何调用"之外。
- 调用关系图的节点现在会说明自己由谁派生——连线对辅助技术是隐藏的，而父节点此前对屏幕阅读器完全不可达。被选中的节点改用 `aria-current` 标记而非 `aria-pressed`：一组中恰有一个被选中，这不是开关。选中的子 Agent 若不在当前显示的派生图里，现在会明说并提供返回路径，而不是仅仅从图中消失；子会话记录尚未加载时显示骨架屏，而不是宣称"没有子 Agent"；技能加载失败会明确提示，而不是留下一个看起来像答案的空菜单。
- 选择性预测：给定一批已打分的决策和一个错误预算，测得的"风险—覆盖"曲线会告诉你能诚实地回答多少——"覆盖率最高的前 62%，错误率不超过 5%"——而不是用原始置信度阈值冒充承诺（那其实只是"未经校准的标尺上的 0.8"）。数据变差时覆盖率随之下降；没有任何可测数据时摘要为 null，而不是给出一个看似笃定的零。这里的弃答是**报告**层面的决定，永远不会变成授权决定。
- 工具结果保留改为对"调用"和"结果"分别打分，因此可以保留调用、只留结果的有界开头加一条重跑提示。按消息折叠的压缩器只能两者同留或同弃——保留侧损失信息，丢弃侧丢掉有用的那一半。高于可弃用下限的分数一定存活；放不进预算的方案会被如实报告为放不下，而不是靠压缩受保护的内容来凑数。
- 一套封闭的结果码词汇，把"我们不知道"与"我们知道，而且很糟"分开，按关注点一一配对，并单列既不属于前者的预算耗尽类别。报告分别统计这两半——因为被告知"3 处失败"、其中两处其实从未尝试的人，会去修一个还不存在的东西。
- 图片除字节数外还受像素数约束。5 MB 的 PNG 是再普通不过的文件，却可以声明 30000 × 30000（纯色几乎压不占空间），而解码它约需 3.6 GB 的 RGBA。各受支持格式的声明尺寸都直接从容器头部读取，不做任何解码；头部被截断或无法识别时报为"未知"，而不是假定它很小。
- 研究预算现在可以为"已放行但尚未上报"的工作预留 token。此前是事后计费，因此两次校验同时在途时预算会双双放行，事后才发现超支；`remainingTokens` 现在真正表示"还花得起多少"。一次预留最多结算一次，因此上报两次的阶段既不会虚增账目，也不会留下悬空的预留。
- 协作日志现在呈现完整的双向交流，而不只是其中一边：你的消息、父 Agent 对运行中子 Agent 的插话、以及发给子 Agent 的输入是三种不同的行，各自带着原文。此前只显示父 Agent 那一半，于是一个正在回应插话的子 Agent 看起来像是完全没有说话。
- 协作日志不再每个流事件都整体重建。它的模型是原地修改的，重绘信号每秒触发约八次，因此遍历会持续扫过每个已绑定子 Agent 模型的每一项——而且是在视图隐藏时照扫，因为日志始终保持挂载。现在行会被复用，其守卫用一个覆盖"行内容可能变化的每一种方式"的签名：新增条目、绑定顾问、调用落定。守卫的第一版以条目 id 为键，是错的——绑定顾问不会新增条目——这一点被测试抓住了。
- 现在可以度量评审模型的稳健性。只在"恰好被你写下的那句措辞"上才有效的评审模型不是评审，是查表；而单次运行分辨不出两者——两者都会给出笃定的标签和通过率。把各个改写版本与选项倒序下的回答记录下来，就能得到翻转率、各变体的准确率与校准度，以及一个配对 bootstrap：它重采样的是**条目**，因此同一问题的两种措辞会一起移动。校准误差与准确率分开报告，因为谁也预测不了谁；bootstrap 在每次抽样中重新计算它们，而不是取平均——这正是多数实现会做错的那一步。
- 审查结论获得了一套封闭词汇。分类若是散文，就无法计数、无法在运行之间做差、也看不出哪一类悄悄翻了一倍，因此每条已发布的规则现在都映射到固定的一组度量之一；"已审查且无问题"是一个明确的结果而非空字符串；每个度量都带有点名它所招致的具体失败的指引——凭空发明性能瓶颈、把风格上的重复当成缺陷、奖励短文件、吹捧投机式架构。若有规则未编码、或映射中出现了并不存在的规则，测试即失败——于是这套词汇无法悄悄地不再是封闭的。
- 活动日志的缓存守卫改为逐条目折叠，而不再是若干聚合量。聚合量——条目数、顾问数、已落定数、时间戳求和——会被真正不同的状态共享：两个调用分别标记 1000 + 2000，与同样两个调用都标记 1500 + 1500，得到的四个数字完全相同而日志截然不同。现在每个条目都贡献自己的标识，以及其对应行会拷贝出来的全部内容，包括被替换过的顾问。
- 现在可以在日志实时更新时阅读它了。读者一滚离末尾，列表就停止跟随，并提供返回途径，而不是每个事件都把读者拽回最新一行。
- JEV 的安全性质现在是可执行的。它们先以散文写成、再落为测试，因为只存在于设计文档里的安全性质，是没有任何东西在检查的性质：没有宿主凭证即禁用、不存在环境端点兜底、无论环境如何都只访问官方路径、拒绝重定向、密钥不出现在任何阅读者可达的界面、未经显式选择则只发送参数元数据、任何提供方回答下都没有 decision 字段、失败时软化并给出分桶原因、以及注入形态的提供方字段被忽略而不是转发。
- 事件流模型在其可能出现的各种顺序下都能正确绑定观察：两个会话复用同一个工具调用号时互不干扰、重复投递是幂等的、迟到的观察会绑定到已落定的卡片上且不改变其标识与时间戳、畸形载荷不会触碰卡片、而"暂不可用"的观察与"没有观察"可区分。
- 等待尚未出现卡片的观察现在有了上限。键是来自事件流的工具调用号，值会一直保留到该 id 的卡片出现为止；因此一条只报出却从不发送这些 id 的事件流，会让这份缓冲在页面整个生命周期内持续增长——也就是说，内存开销完全由链路另一端决定。上限丢弃最旧的一条，并且 id 的位置刷新发生在容量检查**之前**，所以反复报同一个 id 总共只导致一次淘汰，而不是每个事件一次。
- 顾问链路现在可观测了。一组固定计数器记录已回答与不可用的观察，每次失败都归入封闭词汇，提供方 HTTP 状态以数字而非键的形式保留；顾问从未见到的调用则按原因分别计数——已被决定、被策略否决、未配置。任何自由文本都进不来，因此事后无从需要清理，也无法经由这条路把提供方的字符串带进日志。该记录器是可选的，且绝不位于工具调用所依赖的路径上。
