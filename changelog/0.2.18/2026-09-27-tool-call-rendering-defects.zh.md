# 让两个工具说清自己做了什么，并渲染写文件时已算好的 diff

- **Date:** 2026-09-27
- **Type:** fix
- **Scope:** `web`

[English](2026-09-27-tool-call-rendering-defects.md)

工具卡片的标题此前无法说明这个工具为何而设，而写文件会把核心侧已经算好的 diff 丢掉。两者都是同一形态的一行遗漏：一个值由核心产生，交到渲染层，然后在入口处被丢弃。

## 细节

- 搜索卡片现在会在标题里、工具名旁边显示它实际发出的查询。搜索工具的 description——解释这一次搜索为何值得执行的那句话——是必填项、记录在每次调用上，却从未被显示，于是长长一列搜索只剩下一排完全相同的行，除折叠的结果外无从分辨。此前已经套用在 shell 命令"命令行"上的同样处理，现在套用到搜索的"查询"上，并且是按工具逐个指定而非一概假设：取值是纯字符串的第一个参数，就是读者想要的那个。
- `write_file` 或 `edit_file` 卡片会渲染核心为这次编辑产生的 diff。新建或覆盖文件恰恰是行级细节最要紧的写入路径，而它却是唯一把 diff 丢掉的一条：摘要行和尾部说明以纯文本墙的形式出现，而 diff——已经算好、已经在载荷里——从未被显示。路径标签只是装饰，其提取刻意保守：无法识别的行回退为没有标签，而不是错误标签；不含 `@@` 区块头的失败输出与此前一样，仍以纯文本渲染。
- 有一条测试断言了旧行为——没有 description 的卡片不渲染副标题——它被替换而非保留。审批弹窗上展示的预览是另一条路径，仍然只用 description；本次改动仅限于已结算的卡片。
