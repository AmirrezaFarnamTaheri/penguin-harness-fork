# 不再让界面陈述没有依据的数字

- **Date:** 2026-09-27
- **Type:** fix
- **Scope:** `web`

[English](2026-09-27-stop-inventing-numbers.md) · [中文](2026-09-27-stop-inventing-numbers.zh.md)

一次界面审计找出四处界面断言了数据并不支持的内容。其中一处是一个类型对网络层说了谎，而这教会了映射层去编造零。

## 细节

- **每一条快照记录都声称"0 个状态文件"和"0 个记忆主题"。** `SnapshotVersionInfo` 声明了 `fileCount`、`memoryTopicsCount` 和 `activePromptHash`，而线上映射层把三者分别填成 `0`、`0` 和 `""`——因为服务端从未返回过其中任何一个。API 中唯一的 `fileCount` 属于 `MemoryScopeInfo`，是另一个类型、另一个目录。于是，一个拥有真实 Agent State 的项目，在每一行上、永远地显示着一个自信的零。这三个字段已从类型中移除，映射层只映射真正到达的内容，时间线显示它一直就有的体积。一个承诺了网络层从不携带的字段的类型，比缺失的字段更糟：它把缺口对编译器和下一位读者都藏了起来。
- **快照摘要行现在以"Sample data"开头。** 那行其余部分对一个占位数据集是自洽的；其中的文件与记忆计数则不是，现已移除。
- **技能搜索框曾承诺"2,400+ 个技能"。** 这是一个背后毫无依据的硬编码营销数字，出现在一个只列出用户实际安装内容的页面上——而且恰恰是读者最可能认为数字为真的地方。现在它搜索时不再声称一个它无从知晓的规模，并带有无障碍名称。
- **网关的"Router v2 Active"徽标永远不会变成假的。** 它是一个背后没有数据源的硬编码字符串，而这与状态徽标应有的作用恰恰相反。网关响应上没有可绑定的版本字段，因此它是被移除，而不是被编造出来。
- **一个未知的配额值曾以绿色渲染。** "Next Reset Window"以与健康读数相同的绿色显示 `N/A`，于是没人上报的值看起来像是一个正常的值。它现在采用与旁边两个诚实的 N/A 卡片相同的墨色：缺失的值与良好的值不应共用一种颜色。同一张卡片里的 `bg-purple-500` 进度条也改用了强调色 token——本应用声明只有一个强调色，这是该功能中最后的紫色。
