# 一次勾选多个对话，并对它们统一执行可撤销的操作

- **Date:** 2026-09-27
- **Type:** feature
- **Scope:** `web`

[English](2026-09-27-conversation-multi-select.md)

会话列表此前只能对单行做任何事，对多行则无能为力。置顶十二个对话意味着十二次右键；归档一个月的对话同样如此。现在 Cmd/Ctrl+点击某行即可勾选，Shift+点击拉出范围，列表上方的一根操作栏对所有勾选项生效：置顶、取消置顶、归档、取消归档。

## 细节

- 被勾选的对话，永远是你看得见的对话。选择集在每次交互时都与已渲染的行求交集，因此搜索关键词、折叠分组、分页文件夹或切换 Project 都不会在集合里留下已勾选的 id——批量操作读取的正是这个集合，于是不可能归档或置顶一个不在屏幕上的行。操作栏里的计数遵循同一规则：把最后勾选的那行过滤掉，计数会归零，按钮也随之消失，而不是留下一个列表已经无法执行的承诺。
- 屏幕上的行是在点击的那一刻从 DOM 读取的，而不是在渲染过程中收集的——因为渲染过程并不按显示顺序访问它们：分组的文件夹行先于其活跃列表构建，而 DOM 把活跃列表放在前面。否则跨越该边界的 Shift+点击会勾选出一个与你划出的范围并不一致的集合。
- Shift+点击用范围替换选择集，而不是叠加，与 Finder、VS Code 和 Gmail 一致：结果只由参与范围的那两行决定，与此前的任何操作无关。锚点是位置而非选择项，所以取消勾选某行后锚点仍留在原处；没有锚点时的 Shift+点击只勾选一行而不猜测范围——一个能驱动批量操作的选择集，出错时应当偏向"少于你指到的"。
- 批量归档是把单行请求在勾选行上展开，而不是发一个带数组的请求。单行路由会解析该行的归属者，并拒绝调用者 Project 之外的任何行，其余一律回答 404；批量接口必须逐元素重新实现这项检查，而漏掉一个元素的那个版本，会以一个看起来完全合法的响应归档掉另一个 Project 的对话。展开还意味着一行失败不会回滚其余三十九行。
- 批量操作栏里刻意没有删除。它是唯一一个出错无法撤销的批量操作，把它和"置顶"并排，会诱发与拖放归档落错行相同的直觉。每个对话仍然各自带着写明自己标题的确认框：四个弹窗，换来对"到底哪一个没了"的确定。
- 操作栏的控件描述的是它"会做什么"，而不是"当前可做什么"。只要选择集中存在置顶的对话，"取消置顶"就出现；混合选择集只取消其中已置顶的那一半——因为"并非全部已置顶"就把控件置灰，会让最常见的混合情形恰好成为唯一做不了的情形。
- 不使用鼠标也能进入多选。行右键菜单以"多选"开头；被勾选的行就是行按钮本身，带着 `aria-pressed`，而不是旁边再加一个控件——一行一个 Tab 停靠点；而计数在实时区域里播报，因为复选框是装饰性的，而屏幕阅读器用户在按下"归档"之前真正需要听到的就是这个数字。
- 归档当前正在看的那个对话时，会自动展开已归档分组，而不是让它消失在折叠的分组里；批量操作包含它时同样如此。你看得见的东西不会在没有退路的情况下消失。
