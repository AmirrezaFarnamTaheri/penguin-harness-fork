# Bind Jev observations to their tool call, and close the holes a review found

- **Date:** 2026-09-26
- **Type:** fix
- **Scope:** `core`, `server`, `web`, `docs`

[中文版](2026-09-26-jev-binding-and-hardening.zh.md)

The advisory observation is now a footnote on the tool call it describes, and a review of the work landed in this release found and fixed a set of real defects: a policy-blocked tool reported as completed, a transcript fragmentation bug, a data-root split-brain, a deadline reported as a user cancellation, unbounded work in the Benchmark evidence path, and a passing evaluation that passed only because its checker had crashed.

## Details

- A `jev_advisory` hook event is bound to its tool call through the event's new `toolCallId`, and renders inside that call's card with the numbers behind a disclosure. As a stream item of its own it split every Reasoning-and-Tools group it landed in, because a pre-tool-use hook fires between two tool calls. An observation with no call to bind to is dropped rather than floated, and one that arrives before its card is backfilled exactly like an early approval decision.
- The agents dock's view switch is a segmented control in one scope bar beside the Task roll-up, replacing a hand-rolled tab strip under a second tab-strip-shaped label. Both views stay mounted, so the activity log is a live region that announces new rows instead of re-reading its whole history on every switch, and the log's scope no longer changes when a different child is selected. The provider's choice enum is localized, the panel uses the app's existing tone and disclosure primitives instead of a one-off indigo card, and the metric labels meet WCAG AA contrast.
- The activity log reports what happened: a command the policy refused reads as blocked, an approval names who gave it, and rows carry the agent that acted them and a timestamp. Its order is arrival order, which is a total order — the previous comparator ranked tool rows with no timestamp against rows with one and was not transitive.
- Hook subprocesses and interactive terminals keep `PENGUIN_HOME`. Stripping every `PENGUIN_*` variable removed the data-root locator too, so a hook that shells out to `penguin` — the thing `pathPrepend` exists to enable — silently operated on a second, parallel data root. Credentials are still withheld.
- The advisor's own deadline is reported as a timeout rather than a cancellation: the deadline fires the same composed signal the SDK watches, so a slow provider was blamed on the reader. Its circuit breaker is now time-bounded, so ordinary concurrency in one run no longer opens it for every session on the server. Argument keys are no longer sent verbatim — a model-authored key that spells a path is reduced to its last segment, one that looks like a credential is redacted — and a call too large to summarise is reported as omitted rather than answered about partially. Hook stdout and stderr are capped.
- Benchmark evaluation evidence bounds its reads per REQUEST instead of per session, counts the bytes it actually hashed rather than the size the index reported, stops reading when the budget is exhausted, reconciles the Trace index through its mtime gate and forces only on a miss, reads the resolved benchmark path it validated, and chunks its session lookup so a large scoreboard answers instead of failing.
- An evaluation case whose hard-constraint evaluator throws now fails. A thrown evaluator was absent from the results array the gate iterates, so `every()` was vacuously true and the case passed with no notes. Hard constraints are also checked before confidence, and the judge can no longer overturn one.
- Evaluation runs can carry a manifest that binds every input able to change the answer — the dataset, the scoring code, the scored rows, the model's commit id, and this repository's own commit read from git — and an audit that re-derives each of them offline and names which one drifted. A floating model tag is refused at the point of writing, because it is the one input whose later drift is undetectable.
- A spend ceiling that counts calls in flight. The naive ceiling — have we spent more than N? — bounds nothing, because a request's cost is only known when it finishes, so four concurrent calls all pass the check before the first reports. An admitted call now reserves its cost up front, and `spent + reserved` stays within the limit for any interleaving. A duplicated usage event is refused rather than double-counted or silently dropped, and a reservation nothing settles is reclaimed rather than wedging the agent out of calling anything.
- The call graph's nodes now say who spawned them, because the edges are hidden from assistive technology and the parent was previously unreachable to a screen reader. The selected node is marked with `aria-current` rather than `aria-pressed` — one node of a set is selected, which is not a toggle. A selection that is not in the displayed Task's graph says so and offers a way back instead of only being absent from the diagram, a child transcript that has not loaded shows a skeleton rather than claiming there are no subagents, and a failed skill fetch says so instead of leaving an empty menu that reads as an answer.
- Selective prediction: given scored decisions and an error budget, a measured risk–coverage curve says how much can be answered honestly — "the top 62% with at most 5% error" — instead of a raw confidence threshold that means only "0.8 on an uncalibrated scale". Coverage degrades as the data does, and the summary is null rather than a confident zero when there is nothing to measure. Abstention here is a reporting decision and can never become an authorization one.
- Tool-result retention now scores the call and the result separately, so a call can be kept with a bounded head of its output plus a re-run note. A message-folding compactor can only keep both or neither, which loses information on the keep side and discards the useful half on the drop side. A score above the disposable floor always survives, and a plan that does not fit the budget is reported as not fitting rather than met by shrinking something protected.
- A closed vocabulary of outcome codes that keeps "we do not know" apart from "we know and it is bad", paired concern by concern, with a budget exhaustion class that is neither. Reports tally the two halves separately, because a reader told "3 failures" when two were never attempted goes to fix something that does not exist.
- Images are bounded by pixels as well as bytes. A 5 MB PNG is an ordinary file that can declare 30000 × 30000 — a solid colour compresses to almost nothing — and decoding that costs about 3.6 GB of RGBA. The declared size is read from the container header of each supported format without decoding anything, and a truncated or unrecognized header is reported as unknown rather than assumed small.
- The research budget can reserve tokens for work that has been admitted but not yet reported. It charged after the fact, so with two verifications in flight the budget admitted both and only discovered the overrun afterwards; `remainingTokens` now means what may still be afforded. A reservation settles at most once, so a phase that reports twice cannot inflate the books or strand a reservation.
- The coordination log shows the whole exchange, not one direction of it: the human's message, the parent's interjection into a running child, and input delivered to a child are three distinct rows, each with its text. Only the parent's half was shown before, so a child that was answering a steering message looked as though it had said nothing at all.
- The coordination log no longer rebuilds itself on every stream event. Its model is mutated in place and the repaint signal fires about eight times a second, so the walk ran over every item of every bound subagent model continuously — including while the view was hidden, which it is, because the log stays mounted. Rows are now reused behind a signature that covers every way a row's content can change: an item appended, an advisory bound, a call settling. The first version of that guard keyed on item ids and was wrong — binding an advisory adds no item — which the test caught.
- Judge robustness can now be measured. An LLM judge that only works on the exact wording you happened to ship is a lookup table, and one run cannot tell the difference — both produce a confident label and a pass rate. Answers recorded across rewordings and a reversed option order become a flip rate, per-variant accuracy and calibration, and a paired bootstrap that resamples ITEMS so both wordings of one question move together. Calibration error and accuracy are reported separately because neither predicts the other, and the bootstrap recomputes them on every draw rather than averaging, which is the detail that most implementations get wrong.
- Review findings gained a closed vocabulary. A finding whose category is prose cannot be counted, diffed between runs, or noticed growing, so each shipped rule now maps to one of a fixed set of metrics, "reviewed and clean" is an explicit outcome rather than an empty string, and each metric carries guidance naming the specific failure it invites — inventing bottlenecks, flagging stylistic duplication, rewarding short files, praising speculative architecture. A test fails if any rule is left uncoded or any mapping names a rule that does not exist, so the vocabulary cannot quietly stop being closed.
- The activity log's cache guard is a per-item fold rather than a set of aggregates. The aggregates — item count, advisory count, settled count, sum of stamps — are shared by genuinely different states: two calls stamped 1000 + 2000 against the same two stamped 1500 + 1500 produce the same four numbers and a different log. Every item now contributes its own identity and everything a row copies out of it, including a replaced advisory.
- Reading the activity log while it is live is now possible. The list stops following the tail the moment a reader scrolls away from it and offers a way back, instead of yanking them to the newest row on every event.
- The JEV safety properties are executable. They were prose first and tests second, because a safety property that lives only in a design document is one nothing checks: disabled without a host credential, no ambient endpoint fallback, the official path regardless of environment, redirects refused, the key absent from every reader-reachable surface, metadata-only arguments unless opted in, no decision field under any provider answer, fail-soft with a bucketed reason, and injection-shaped provider fields ignored rather than forwarded.
- The stream model binds an observation across the event orders it can arrive in: two sessions reusing a tool-call id stay apart, a duplicate delivery is idempotent, a late observation binds to a settled card without shifting its identity or timestamp, a malformed payload leaves the card untouched, and an unavailable observation is distinguishable from an absent one.
- Observations waiting for a card that has not arrived are now capped. The key is a tool-call id off the wire and the value was held until a card with that id turned up, so a stream naming ids it never sends grew the buffer for the life of the page — a memory cost set entirely by the other end. The cap drops the oldest, and refreshing an id's position happens before the capacity check, so hammering one id costs one eviction in total rather than one per event.
- The advisory path is now observable. A fixed set of counters records answered and unavailable observations, each failure bucketed into a closed vocabulary with provider HTTP statuses kept as numbers rather than keys, and the calls the advisor never saw counted separately by reason — already decided, policy-vetoed, or not configured. Nothing free-form enters any of it, so there is nothing there to redact later and no provider string can reach a log through it. The recorder is optional and never sits on the path a tool call depends on.
