PenguinHarness fork 0.2.16 完成 HPORT 供体归档的整体移植：十一个供体轨道归并为八个二阶平台平面，每个平面都有真实的源桶与独立的测试套件，平台自身的循环也获得了带有运行时调用者的重复工具守卫。

## 变更

- HPORT 供体语料已完整移植。123 个受跟踪归档中 118 个完成移植，另有 5 个在供体磁盘上确实缺失，现在如实记录为 `absent`，而不是被静默标记为完成。十一个轨道映射为八个平台平面——智能体 OS 核心、多智能体群体与共识、代码拓扑与自愈、统一工具网格与身份、向量与可视化座舱、科学发现、零信任沙箱以及无头终端——`codegraph`、`memory` 与 `prompts` 成为根导出、tsup 入口与包 `exports` 路径。
- `RepeatToolGuard` 现在有了运行时调用者。它观察 ReAct 循环中的已批准调用路径（被拒绝的调用从未执行，因而不构成循环证据），先做 JSON 解析使键序无法绕过深度比较，并将提醒作为消息追加到该轮工具输出之后，构造上不阻塞。新的任务边界会重置调用链。
- 恢复了此前在本分支上丢失的能力：服务端审计读取路径（HMAC 验证回执与受限字节窗口）、共识变更路由与只读的定时任务看板投影、记忆搜索、Web 循环事件流及其守护审计面板，以及 Windows 的 `taskkill /T /F` 进程树强制终止。
- 移植代码中的正确性修复：codegraph 的按语言注释语法与 Go 参数名、检索的下推先过滤后取 topK、图重摄入的幂等与事务化、UTF-8 FNV-1a 哈希、`register()` 处对注入标记的拒绝，以及跟踪记录中被写反的缺失归档检查。
- 修复了四个仅在 Windows 上通过、在 Linux 与 macOS 分片上失败的测试：环境信息在翻译路径时现在遵循其注入的事实而非读取当前内核；舰队审计的临时文件名每次写入唯一，两个记录刷新同一轨迹时不再竞争导致 `ENOENT`；浏览器僵尸清理被限定在其自身的进程组内，并等待被终止的进程真正退出。

## 范围说明

五个缺失归档在供体磁盘上不存在，因此如实报告，不会被静默标记为完成。桌面预发布更新需通过 `PENGUIN_UPDATE_ALLOW_PRERELEASE` 明确启用；本版本未提供命名的 stable/canary 通道切换。Fork 桌面构建未经签名。此 Fork 不发布上游 npm 包、OSS 镜像或 Docker 镜像。

## 安装

请下载此 Fork 的 GitHub Release 构件，适用于 Linux 或 macOS（x64/arm64）以及 Windows（x64）。平台归档包含所需运行环境；通用归档需要 Node.js 24 或更高版本。
