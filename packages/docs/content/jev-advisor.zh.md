# 运行 Jev 顾问

可选的 [Jev 顾问](configuration#可选-jev-顾问宿主组合)是宿主组合、有界且**仅供参考**。本页是运维视角：如何启用、什么会跨越提供方边界、如何读计数器，以及当某次运行报告 `unavailable` 时该怎么做。

## 它是什么，以及它不是什么

一条 Jev 观察是模型对"这次提议的工具调用是否契合任务"的意见。它会被记录、显示在对应调用的卡片上，并被计数。仅此而已。

| 它可以 | 它不可以 |
|---|---|
| 作为脚注出现在工具调用旁 | 允许、拒绝或满足审批 |
| 说这次调用看起来有风险、慢或不合适 | 改变 Project 命令策略 |
| 被计入延迟与可用性 | 挑选工具，或改写模型的请求 |
| 消耗令牌与墙钟时间 | 曾经、并且永远不会阻断执行 |

**权威顺序不变且不可协商**：Environment 权限 → Project 命令策略 → 人工审批回调。到达 Jev 的调用已经通过这三者，而 Jev 只会为"没有任何其他环节做出决定"的调用运行。如果 Jev 认为某次调用没问题而命令策略否决了它，它就是被否决了。如果 Jev 认为某次调用很糟糕而其他环节都没有反对，它就会执行。

## 启用

在服务端设置一个变量，这就是全部开关：

```bash
PENGUIN_JEV_API_KEY=<宿主自有密钥>   # 未设置 ⇒ 禁用，工具路径与历史行为逐字节一致
PENGUIN_JEV_MODEL=jev-latest          # 可选；这是宿主的选择，不是 Agent 的
```

刻意不提供 Agent 级开关。Agent 可以编辑自己的 `system_config.yaml`，因此存在那里的凭证或端点可能被"被观察的"那个 Agent 改写。密钥留在服务端环境变量中，绝不进入 Agent State、Trace 事件或任何流载荷。

## 什么会跨越边界

**默认：仅元数据。** 对每次尚未决定的工具调用，顾问会发送工具名、确定性权限、参数的**键**与**值类型**、参数是否解析为 JSON，以及参数数量。它不发送参数值、提示词、文件内容或对话记录。

关于这些键本身有两点值得知道。形如路径的键只保留最后一段，形似凭证的键会被清理——键由模型生成，所以模型能放进键里的东西，和能放进值里的完全一样。

**显式选择：参数值。** `createJevAdvisor({ includeArguments: true })` 会连值一起发送。可识别的凭证形态会被清理，但内置清理器无法证明一个不透明的值是安全的。请把它当作一次明确的数据出境决策，而不是默认行为。

**绝不外发**：除 `Authorization` 请求头以外的任何位置的 API 密钥；任何用户可见诊断中的提供方原始响应文本；日志、Trace 或计数器中的提供方错误正文。

## 读计数器

顾问暴露一组固定计数器（`@prismshadow/penguin-core/jev` 中的 `AdvisoryActivityRecorder`）。其中没有任何自由文本进入——每个值要么是计数、要么是时长、要么是封闭词汇里的一个词——因此事后没有需要清理的东西，提供方字符串也无法经由这条路进入日志。

| 计数器 | 含义 |
|---|---|
| `answered` | 产生了可用答案的观察 |
| `unavailable` | 没有产生答案的观察，无论何种原因 |
| `skippedDecided` | 在顾问被触及之前就已被 hook 决定的调用 |
| `skippedPolicy` | 在顾问被触及之前就被命令策略否决的调用 |
| `skipped` | 根本没有组合出顾问的调用 |
| `latencyPercentiles()` | 已回答调用的 p50/p95，取自一个有界采样环 |
| `byReason` | 失败分布：`timeout`、`cancelled`、`circuit_open`、`connection_error`、`invalid_response`、`provider_http` |
| `providerHttpStatuses` | 提供方状态码计数，以数字而非指标键的形式保留 |

`skippedDecided` 与 `skippedPolicy` 是判断顾问是否物有所值的数字：`skippedDecided` 很高意味着大多数调用根本不需要意见，而这些调用所消耗的延迟预算或许更值得花在别处。

## 当某次运行报告 `unavailable`

工具调用会与完全没有配置顾问时完全一致地继续。没有任何东西被阻断，顾问也不会自行重试，而原因是分桶结果而非提供方字符串。

| 原因 | 发生了什么 | 该做什么 |
|---|---|---|
| `timeout` | 调用超过宿主的硬截止时间 | 无需处理——这正是在起作用。若持续出现，降低并发或提高截止时间 |
| `cancelled` | Session 被中止或回合被停止 | 无需处理；是用户做的 |
| `circuit_open` | 连续失败打开了本地熔断器，因此没有发出任何请求 | 见下文 |
| `connection_error` | DNS、TLS 或连接失败 | 检查宿主的出网路径与代理 |
| `invalid_response` | 提供方返回了未通过校验的内容 | 通常是提供方侧变更；原始正文刻意不予展示 |
| `provider_http` | 提供方返回了 HTTP 错误 | 状态码在 `providerHttpStatuses` 中 |

**熔断器。** 连续三次失败后打开，保持 30 秒；该窗口结束时只放行一个半开探测。它按时间界定而非纯按次数，因此繁忙运行中的单次网络抖动（多个调用在同一截止时间超时）不会为服务端所有会话打开熔断。由调用方发起的取消永远不计入其中。卡住的提供方被报告为 `timeout` 而非 `cancelled`：截止时间属于宿主，把提供方的延迟归咎于用户是错的。

## 关闭

取消设置 `PENGUIN_JEV_API_KEY` 并重启。不会组合出顾问，不会注册 hook，不会发出任何事件，工具路径就是历史的那条。关闭它始终是安全的：系统中没有任何东西依赖观察结果，而这正是让这个开关在故障时可以安全拨动的性质。

## Jev 系列变体

此处仅集成了托管的 System One API。`JEV-Family/` 中的语料还包含其他名称相近的产品——fast、compact、Go、Python、Rust、离线与企业版变体——**它们在此一概不受支持**。共用名称并不意味着兼容：任何适配器都必须满足同一份契约（有界且仅元数据的输入、硬截止时间、禁止重定向、禁止无界重试、封闭的输出词汇，以及仅供参考的语义），并通过同一套一致性测试，才会被提供。在此之前，请把其他所有变体视为超出范围，而不是可互换的后端。
