# F8 — Measured contrast and token-color fixes (2026-10-02)

F8 asks for one thing done properly: measure the colors the app actually paints, fix what is below
the floor, and stop keeping the arithmetic in two places. The card also names four historical
ratios (1.67 / 2.77 / 2.98 / 2.15:1) that were supposed to be reconciled against current screens.

## F8.1 — The historical ratios, reconciled honestly

**They are not attributable to any site in this repository.** The numbers exist only in the plan
card; no audit document, comment or test in the tree records them, and no live color measures them
today. Rather than pretend a mapping, the reconciliation is:

| Historical claim | Current state |
| ---------------- | ------------- |
| A focus ring around 1.67:1 | **Confirmed and already fixed.** The old ring was `rgb(107 114 128 / 0.4)` — gray-500 at 40% alpha, compositing to `#c4c7cc` on white = **1.70:1**, on every focusable element. `styles.css` now uses `--accent-bg`: 17.74:1 on white, 19.08:1 on the dark base. F8's new alpha primitive measures the old value exactly (asserted), so the claim is now reproducible rather than quoted. |
| The other three (2.77 / 2.98 / 2.15) | **No live site measures them.** The classes they most plausibly described — the token palette and the muted label grays — are measured below; none is near those values today. Recorded as unattributable, not as fixed-by-assumption. |

Re-measured today (WCAG 2.x, via the new primitives; "was" values are what this package found):

| Site | Theme | Foreground / background | Ratio | Verdict |
| ---- | ----- | ----------------------- | ----- | ------- |
| Body text | light | `#111827` / `#ffffff` | 17.74:1 | pass |
| Body text | dark | `#f3f4f6` / `#000000` | 19.08:1 | pass |
| Secondary text (gray-600) | light | `#4b5563` / `#ffffff` | 7.56:1 | pass |
| Secondary text (gray-400 on gray-950) | dark | `#9ca3af` / `#000000` | 8.27:1 | pass |
| Muted label (gray-500) | light | `#6b7280` / `#ffffff` | 4.83:1 | pass |
| **Code gutter line numbers** | light | `#9ca3af` / `#ffffff` | **2.54:1 → 4.83:1** | **fixed** (gray-400 → gray-500) |
| **Code gutter line numbers** | dark | `#4b5563` / `#000000` | **2.78:1 → 8.27:1** | **fixed** (gray-600 → gray-400) |
| Focus ring (accent) | both | `#111827` / white, `#f3f4f6` / black | 17.74 / 19.08:1 | pass (fixed in an earlier package) |

| Disabled button text | light | `#9ca3af` / `#f3f4f6` | 2.09:1 | **exempt** (1.4.3/1.4.11) — measured and recorded, not waved through |

The two gutter failures were real, user-visible text in a component every code block renders; they
were found by measuring, not by trusting a comment.

## F8.2 — Contrast primitives

`packages/web/src/lib/contrast.ts`, and the palette suite now delegates to it instead of carrying a
private copy of the formula:

| Export | Purpose |
| ------ | ------- |
| `parseColor` | `#rgb`, `#rrggbb`, `#rrggbbaa`, `rgb()`, `rgba()` with 0–255 channels / 0–1 alpha; anything else → `null` (never a guess) |
| `composite` | sRGB alpha compositing — what the browser actually paints |
| `relativeLuminance` | WCAG 2.x formula; a translucent color returns `null` (it has no luminance of its own) |
| `contrastRatio` | ratio of two colors, each composited over an explicit `base` when translucent |
| `requiredRatio` | 4.5 text / 3 large-text, icon, focus-ring, chart-fill / **`null` for disabled text** |
| `evaluateContrast`, `describeContrast` | verdict shape and a one-line rendering for failure messages and this table |

## F8.3 — Incremental component fixes

Exactly two declarations changed, one per theme, each independently revertible:

```css
/* light */ @apply bg-white text-gray-400;   → @apply bg-white text-gray-500;
/* dark  */ @apply bg-gray-950 text-gray-600; → @apply bg-gray-950 text-gray-400;
```

No other component was touched: nothing else measured below its floor, and "fix what you cannot
measure" is how a palette drifts. The stylesheet now carries the measured numbers next to each
value, so the next reader sees why the shade is what it is.
