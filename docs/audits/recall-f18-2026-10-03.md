Before this card: `TruncatedToolOutputArchive` (`packages/core/src/environment/tools/
truncated-tool-output-archive.ts`) stored compressed-away output under the Session's scratchpad and
the `recall_output` **tool** could read it, but only the model had a handle: the archive was built
by `Environment` and kept **private** (`#archive`, `environment/index.ts:191`), nothing in
`packages/server`, `packages/cli` or `packages/web` mentioned `recall` at all, and the result note's
`recallId` was opaque to a human. So the whole feature was model-only: a person reading a Session
could see that output had been archived and could not get it back. The id's shape (12 or 32
lowercase hex) existed only inside the tool's page-slicing code, as a local concern.

## Change

1. **F18.1 — one shared seam, raw paths invalid.** `packages/core/src/environment/tools/
   recall-output.ts` now exports `RECALL_ID_PATTERN` (`^(?:[a-f0-9]{12}|[a-f0-9]{32})$`),
   `isValidRecallId` (trim + lowercase), `RECALL_OUTPUT_PAGE_CHARS` (12 000), `sliceRecallPage(
   text, offset, pageChars)` → `{status:"ok", page, nextOffset|null, totalChars} |
   {status:"invalid-offset", totalChars}` and the `RecallPageSlice` type; the `recall_output` tool
   calls the slicer, so the model path and every new consumer share one implementation of the
   offset/surrogate-pair rules. The barrel (`packages/core/src/environment/index.ts`) exports the
   seam plus `TruncatedToolOutputArchive` and its result/stats types — host surfaces need to build
   their own archive, because `Environment` keeps its instance private (that privacy is deliberate;
   this card does not change it). The id shape is what makes traversal unrepresentable: an id
   contains no `/`, no `.`, no separators, so it can never be a path component or an extension.
2. **F18.2 — server route** (`packages/server/src/http/routes/sessions.ts`, immediately before the
   scratchpad route): `GET /api/sessions/:sessionId/recall/:recallId?offset=<n>` →
   `RecallPageResponse {recallId, offset, page, nextOffset|null, totalChars}` for the owner of the
   Session (the route resolves through the same `resolveSession`/authz path as its neighbours).
   Refusals are distinct because the fix differs: 400 `recall_id_invalid` / `recall_offset_invalid`,
   404 `recall_unavailable` (never stored here, **or** stored by another Session/Project) versus 404
   `recall_expired` (entry aged out of the bounded store), 416 `recall_offset_out_of_range` whose
   message carries the real text length. The store is built per request from
   `path.join(sessionScratchpadDir(config.root, row.projectId, row.agentId, row.sessionId),
   "truncated-tool-output")` — inside the resolved Session's own scratchpad, so authorization is
   the Session resolution and not a path the caller supplied.
3. **F18.2 — CLI** (`packages/cli/src/commands/recall.ts`, registered in `src/index.ts` with the
   other commands): `penguin recall <recallId> [sessionId] [--offset n] [--pages n] [--json]
   [--project-id id] [--agent-id id] [--server url]`. The id is validated locally against the core
   shape before any request, so a typo or a pasted path fails with "it names no file" and never
   becomes a URL; the session argument resolves exactly like `penguin logs` (omitted = the agent's
   latest session). Pages stream to stdout as they arrive — the stored entry can be megabytes, and
   nothing accumulates it — and `--json` is NDJSON (one object per page) for the same reason.
   `--pages` is a soft yield (exit 0) that prints the offset continuing the read. Failures map
   `recall_id_invalid` / `recall_expired` / `recall_unavailable` / `recall_offset_*` to sentences
   per code; anything else rethrows, so an unexpected error keeps its own text.
4. **F18.2 — web affordance** (`packages/web/src/features/chat/recall-chip.tsx`, rendered by
   `tool-call-card.tsx` below the output it belongs to, outside the card's own disclosure). Pure
   `packages/web/src/lib/recall.ts` holds the parsing and paging: `parseRecallMetadata` scans
   balanced JSON objects in the note and returns the first with a valid id (a path-shaped string in
   prose is not metadata); `recallPageUrl` re-validates and percent-encodes the id;
   `collectRecallText` is bounded by a page limit, streams each page to `onChunk`, and on a
   mid-read failure returns `partial` with the text already read **and** the resume offset rather
   than discarding the prefix. The chip: native button with `aria-expanded`/`aria-controls`, a
   labelled `region` panel, `aria-live="polite"` status, Escape closes with focus kept on the chip,
   8 pages per click with "Load more", nothing fetched until opened, and reads through the app's
   `apiFetch` with `handleUnauthorized: false` so an expired archive entry is not treated as an
   expired session. The card's decision is a pure exported `recallAffordance(item, sessionId)`
   (Session known + output settled + note publishes a valid id), which is what a node-only web suite
   can hold still.
5. **Docs:** `penguin recall` sections in `packages/docs/content/cli.en.md` and `cli.zh.md` (options
   table, the three failure kinds, the streaming/soft-yield behaviour), and `recall_*` strings in
   `packages/web/src/lib/strings-en.ts` / `strings-zh.ts` (the server's error codes were already
   localized there by the route package).

## Compatibility

- **Old readers/clients:** none of the changed surfaces had a reader before this card. The server
  adds a route (no existing route changed shape), the CLI adds a command (no existing command's
  output changed), the web adds a component and two context/component fields (`ctx.sessionId`,
  and the card renders the chip only when a note publishes an id). `recall_output` tool behaviour is
  unchanged — the F18.1 seam was extracted with the tool calling the slicer, and its suite stayed
  green.
- **Old ids:** the 12-hex legacy shape is accepted everywhere the 32-hex shape is (pattern, parser,
  CLI validation), so entries issued before this card remain retrievable.
- **Promised lifetime:** `RECALL_LIMITS` (200 entries / 64 MiB / 30 days) is untouched; expiry
  reporting changed only from "the model sees `dropped`" to additionally naming `recall_expired` on
  the route.
- **Scope ownership:** the archive stays private to `Environment`; host surfaces construct their own
  instance from the Session's scratchpad (`sessionScratchpadDir`, already used by the neighbouring
  scratchpad route). Rollback per the card: hide the chip; no migration is needed because no
  persisted format changed.
- **Auth:** the route rides the existing Session resolution/authz path; the web chip deliberately
  sets `handleUnauthorized: false` so an archive refusal cannot log a user out.
- **`docs/status-ledger.json` deliberately unchanged.** No existing claim's status changes, and the
  new consumption is not representable: a `Shipped` claim needs a runtime chain of *relative-path*
  imports ending in a call to the symbol, and this seam's consumers import it through the
  `@prismshadow/penguin-core` package specifier (the server route) or live in the same file as the
  slicer (the `recall_output` tool). The one claim that mentions recall,
  `bounded-stream-capture`, is about a different module (`trace/bounded-capture.ts`, still
  unconsumed) and its reason stays accurate. Inventing a ledger entry that the checker cannot
  verify would be worse than recording that the ledger's model does not cover this shape.
