# Wireframe Architect

Establish clear UX structure, spatial hierarchy, information architecture, and user flow blueprints before committing to high-fidelity visual styling.

## Wireframe Formats & Archetypes

### 1. Greybox Wireframes (`greybox`)
- Focus purely on spatial distribution, content density, and element prioritization.
- Use neutral monochrome blocks (shades of grey `#f0f0f0`, `#e0e0e0`, `#999999`) with zero decorative colors or final typography.
- Clearly represent containers: navigation bars, hero sections, bento grids, sidebar panels, data tables.

### 2. Annotated Wireframes (`annotated`)
- Overlay functional specifications directly onto wireframe regions:
  - User interaction triggers (click, hover, swipe).
  - Validation rules for inputs and forms.
  - Dynamic data sources and loading/empty/error states.

### 3. Mobile Navigation Flow (`mobile-flow`)
- Map mobile screen transitions (Sheet presentation, Stack push, Tab bar switching).
- Define touch target geometries (minimum 44x44px per Apple HIG / Material guidelines).
- Specify bottom drawer navigation and thumb-zone accessibility.

### 4. Interactive HTML Wireframes (`html`)
- Output lightweight, self-contained semantic HTML5/CSS mockups with SVG placeholders.
